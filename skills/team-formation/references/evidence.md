# Design hypotheses behind the rules
**These are design hypotheses, not evidence that the formation works.** The sources motivate the rules; none tests this
formation. Whether the team beats one agent is measured per campaign against the baseline (SKILL.md, Setup step 6).
None of these sources has been checked against the original yet. Wu–Wang–Evans, Uzzi, Diehl–Stroebe,
Stasser–Titus, Nemeth and Lazer–Friedman are well-known papers (check details); Wynn 2025, Kim 2025,
the "Lipshitz guide" and claude-for-researchers could not be confirmed and must be found before citing.

| Rule | Motivating source (unverified) |
|---|---|
| two phases (small isolated exploration → dense development) | Wu, Wang, Evans 2019 (Nature): small teams disrupt, large teams develop |
| cross-field ideas anchored through No. 10 | Uzzi et al. 2013 (Science): atypical combinations anchored in conventional ones |
| submit ideas before seeing others | Diehl & Stroebe 1987: production blocking in brainstorming |
| pass only what only you know | Stasser & Titus 1985: hidden profiles |
| defenders use a different model family | Nemeth 2001: authentic dissent beats role-played devil's advocate |
| no voting, only evidence | Wynn et al. 2025: debate can flip correct answers to wrong |
| prover keeps 1–2 agents | Kim et al. 2025: coordination overhead, saturation on sequential/tool-heavy tasks |
| tests outside implementers' reach | Lipshitz guide (2026): Claude edits tests to pass instead of fixing code |
| check citations exist | Lipshitz guide: invented paper contents and citations |
| several independent breakers | Lipshitz guide: re-running the same prompt finds more issues |
| handoff in files, pre-compact hooks | claude-for-researchers: task logs beat auto-memory; hooks save state before compaction |
| keep one member off-consensus | Lazer & Friedman 2007: inefficient networks keep diversity |
